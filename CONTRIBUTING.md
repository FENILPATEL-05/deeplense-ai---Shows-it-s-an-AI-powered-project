# Contributing to Deeplense

Thank you for your interest in contributing to Deeplense! However, please note that this project has a **custom license** that requires explicit permission before contributing.

## Before You Contribute

**IMPORTANT**: This project is under a custom license. Before making any contributions:

1. **Contact the author** - Reach out to Fenil Patel on GitHub
2. **Request permission** - Clearly state your intended contribution
3. **Get written approval** - Ensure you have explicit permission before proceeding

## How to Request Contribution Rights

1. Visit: https://github.com/FENILPATEL-05
2. Open an issue or discussion about your contribution idea
3. Describe what you'd like to contribute
4. Wait for explicit approval from Fenil Patel

## Contribution Process (After Getting Permission)

If you receive permission to contribute:

1. **Fork the repository**
   ```bash
   git clone https://github.com/FENILPATEL-05/deeplense-ai---Shows-it-s-an-AI-powered-project.git
   ```

2. **Create a feature branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make your changes**
   - Follow the existing code style
   - Add comments for complex logic
   - Test your changes locally

4. **Commit with clear messages**
   ```bash
   git commit -m "feat: Add description of your feature"
   ```

5. **Push to your branch**
   ```bash
   git push origin feature/your-feature-name
   ```

6. **Submit a Pull Request**
   - Include description of changes
   - Reference any related issues
   - Wait for review and approval

## Code Style Guidelines

### Python (Backend)
- Use PEP 8 style guide
- Add type hints where possible
- Include docstrings for functions
- Maximum line length: 100 characters

### TypeScript/React (Frontend)
- Use Prettier for formatting
- Follow React best practices
- Component names in PascalCase
- Props interfaces prefixed with `I` or `Props`

### Commit Messages
- Use conventional commits: `feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:`
- Be descriptive and concise
- Example: `feat: Add advanced search filter UI`

## Testing

Before submitting a PR:
1. Test your changes locally
2. Ensure no breaking changes
3. Verify backend tests pass
4. Check frontend builds without errors

## Documentation

If adding new features:
1. Update relevant documentation
2. Add examples to README if applicable
3. Document API endpoints if changed
4. Include configuration examples

## License Compliance

- Must respect intellectual property rights
